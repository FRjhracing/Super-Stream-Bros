## End goal (2026-10-19)
One upload-ready VOD per tournament: **all tournament sets back to back, with a corrected overlay**, audio +10dB, YouTube chapters. Built from four inputs:
1. The raw stream recording (overlay is baked into it, including live mistakes/delays).
2. Main Setup `.slp` replays (game start/end times, characters, colors, winners).
3. start.gg set data (entrants, round names, final scores), the same data the Stream Updater pulls.
4. The overlay source (layout/art), used to re-render a correct overlay on top of the recorded one.

## Folders
- `Recording-IN\`: raw, unedited recordings waiting to be cut. The cutter reads from here. Filename = recording start time (`YYYY-MM-DD HH-MM-SS.mp4`, local).
- `Recording-BACKUP\`: untouched copies for testing. Never written to by scripts.
- Output folder: TBD (e.g. `Recording-OUT\`).
- ffmpeg/ffprobe (full build, 2026-10-15): `tools\ffmpeg\bin\` (not on PATH).

## How it is intended to work
1. Read the recording's start time from its filename.
2. Read Main Setup replays (reuse `slippi_scan.py`); compute each game's offset in the video = `startAt` (UTC → local) − recording start, plus a calibration offset.
3. Drop games from before the recording began; group the rest into sets (shared Stage 3 logic) and match them to start.gg sets.
4. Reconcile each set against start.gg's game count (see Edge cases), then build a cut list with padding.
5. Render a corrected overlay per game state (names, tags, score, characters/stock icons, round) and composite it over the recorded overlay with ffmpeg.
6. ffmpeg trims and joins, applies +10dB gain with a safety limiter, and runs the last segment to the end of the file.
7. Output the video, a chapter list, and a review report (every assumption and manual override).

## Edge cases and manual overrides
Replays and recordings are not always clean, so the cutter should detect mismatches, flag them, and accept a per-recording **overrides file** (e.g. `Recording-IN\<recording name>.overrides.json`) instead of hard-coding fixes.

- **Missing replay at the start (Protocol #55, not the norm):** the first game of the first set has no replay. The recording started during a player pause, so that game was played but not captured on the drive. **Keep this set.** Detection: start.gg says N games, replays show N−1, and the missing game is before the first replay → the set starts at a manually given timestamp (or the recording start) instead of the first replay.
- **General rule:** for every set compare start.gg game count with matched replays. Fewer replays → flag (missing game: start, middle or end); more replays → probably a handwarmer or friendly, trim from the front (same rule as Stage 3).
- **Recording mistakes** (late start, gaps, stops): overrides can set a manual start/end for a set or game, or skip one.
- **Overlay mistakes/delays:** the Stream Updater only writes its current state to `StreamUpdater\output\` and keeps no history, so the live overlay timeline cannot be recovered from it. The corrected overlay is rebuilt from start.gg + replay winners instead. Score ticks up at each game end, not when the operator clicked.
- Clock offset between the stream laptop and the Wii/Slippi timestamps: calibrate per recording against one known moment (e.g. a game start visible on stream), stored in the overrides file.
